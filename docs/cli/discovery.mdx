## whoami

```bash
appstore whoami
appstore --json whoami
```

Shows the key id, issuer id, key type (team or individual), the account it came from, and whether read-only is on. It does not call Apple.

## search / capabilities

```bash
appstore search phased
appstore capabilities --json
```

## ops

```bash
appstore ops list
appstore ops list subscriptions
appstore ops describe appstore_create_version
```

## api

Every App Store Connect API operation, generated from Apple's OpenAPI spec (see [Full API coverage](/concepts/full-api-coverage)):

```bash
appstore api list --search "custom product pages"          # search names, paths, summaries
appstore api list --group betaGroups --method POST         # filter by resource group and method
appstore api list --generated --json                        # every generated op as JSON
appstore api describe appstore_api_beta_groups_create_instance
appstore api call appstore_api_apps_app_clips_get_to_many_related --param id=1234567890 --param limit=10
appstore api call appstore_api_apps_get_collection --param filter[bundleId]=com.example.app --all --max-items 500
appstore api call appstore_api_beta_groups_create_instance --body @group.json --confirm
```

| Flag | Meaning |
|------|---------|
| `-p, --param key=value` | Repeatable. Path (`id=…`) and query parameters by Apple's name (`filter[platform]=IOS`, `fields[apps]=name,bundleId`, `include=builds`, `limit=50`). Repeating a key builds a list. |
| `-b, --body` | JSON:API body, inline or `@file.json` |
| `--all`, `--max-items` | GET collections: follow pagination (default cap 1,000 items) |

`api list` and `api describe` print tables, or JSON with `--json`; `api call` always prints JSON. Generated operation names also work with `appstore ops describe` and `appstore ops call`.

### Raw requests

For a path you already know (`appstore api request …`; `request` can be left out):

```bash
appstore api GET /v1/apps/1234567890/appClips
appstore api GET /v1/apps --query "filter[bundleId]=com.example.app" --query limit=1
appstore api PATCH /v1/apps/1234567890 --body '{"data":{"type":"apps","id":"1234567890","attributes":{"contentRightsDeclaration":"DOES_NOT_USE_THIRD_PARTY_CONTENT"}}}' --confirm
```

Paths must start with a version (`/v1`, `/v2`, …). Non-GET calls need `--confirm` and are refused in read-only mode.
