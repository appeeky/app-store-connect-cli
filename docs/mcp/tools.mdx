title: MCP tools
description: How MCP tools map to the operations registry, with examples.
---

Every curated operation in `ASC_OPS` is a tool with the same name and argument schema. The 1,303 [generated API operations](/concepts/full-api-coverage) (one per endpoint in Apple's OpenAPI spec) are not registered one by one; three tools reach them instead:

| Tool | Description |
|------|-------------|
| `appstore_search_operations` | Search generated and curated operations by words (`query`), `group`, `method`; returns name, method, path, write and parameter names (`limit`, default 20) |
| `appstore_describe_operation` | Full parameters of one operation (types, enums, maximums, pagination) and its JSON:API request body: required attributes and relationships with types, plus an example |
| `appstore_call_operation` | Run any operation by `name` with `args` (and `account` on `appstore-mcp`) |
| `appstore_search_capabilities` | Search the curated tools by keyword |
| `appstore_list_capabilities` | List the curated tools |

`appstore_call_operation` validates arguments before any request, refuses writes in read-only mode, and on the hosted server follows the same rules as the REST API (writes only with `X-ASC-Allow-Writes: true`, CLI-only operations refused).

## Examples

**Find an app**

```json
{ "name": "appstore_find_app", "arguments": { "bundleId": "com.example.app" } }
```

**Unanswered low ratings**

```json
{
  "name": "appstore_list_customer_reviews",
  "arguments": { "appId": "1234567890", "rating": [1, 2], "hasResponse": false, "limit": 20 }
}
```

**Latest build**

```json
{ "name": "appstore_get_latest_build", "arguments": { "appId": "1234567890", "marketingVersion": "2.4.0" } }
```

**Submit (write)**

```json
{
  "name": "appstore_submit_version",
  "arguments": { "appId": "1234567890", "versionId": "VERSION_ID", "platform": "IOS" }
}
```

**Any endpoint, by name**

```json
{ "name": "appstore_search_operations", "arguments": { "query": "app clips", "method": "GET" } }
```

```json
{
  "name": "appstore_call_operation",
  "arguments": {
    "name": "appstore_api_apps_app_clips_get_to_many_related",
    "args": { "id": "1234567890", "fields": { "appClips": ["bundleId"] }, "limit": 10 }
  }
}
```

**Create something (write)**

```json
{
  "name": "appstore_call_operation",
  "arguments": {
    "name": "appstore_api_beta_groups_create_instance",
    "args": {
      "body": {
        "data": {
          "type": "betaGroups",
          "attributes": { "name": "QA" },
          "relationships": { "app": { "data": { "type": "apps", "id": "1234567890" } } }
        }
      }
    }
  }
}
```

**Raw request**

```json
{
  "name": "appstore_request",
  "arguments": { "method": "GET", "path": "/v1/apps/1234567890/appClips", "query": { "limit": 10 } }
}
```

With `appstore-mcp`, tools also take `account` to pick a key from the config. If the `appId` is registered under exactly one account, it is picked automatically.

CLI equivalents: `appstore ops call <tool> '<json>'` and `appstore api call <name> --param k=v`. Catalogs: [Operations reference](/reference/operations) (curated) and [API operations reference](/reference/api-operations) (generated).
